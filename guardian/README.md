# aemeath-guardian（Aemeath.exe）

守护进程（`Aemeath.exe`），是第一个启动的进程：

1. **单实例**：每个用户只运行一个（互斥体名带用户 SID）。已有实例时直接退出。
2. **检查 usbip-win2 驱动**：
   - 卸载注册表项里的版本；
   - `usbip.exe --version`（与注册表不一致时以它为准，只记日志）；
   - 驱动服务 `usbip2_ude` 必须在运行（它是根枚举的虚拟主控制器，没有挂载设备时也在运行）；
   - 版本不低于 0.9.8.0（0.9.7.8 是已知有问题的版本）；
   - `usbip.exe port` 自检：输出要么为空，要么至少能解析出一个条目。

   任何一项不满足：显示原生 TaskDialog 说明原因（中文或英文，按配置里的语言偏好，否则按系统界面语言）。未安装或版本过旧时引导安装附带的驱动（经 UAC 静默安装）；其他情况只说明原因，以退出码 2 退出，不拉起引擎和主程序。比附带版本更新的驱动正常使用，只记日志。
3. **拉起并监视**引擎（`aemeath-host.exe`）与主程序（`aemeath-app.exe`）：
   - 两者与守护进程放在同一目录，收到与守护进程相同的参数（数据目录、端口、管道名、共享内存名）。
   - 先拉起引擎，再拉起主程序。
   - 异常退出时按 1、2、4、8、16、30 s 退避重新拉起；连续运行 60 s 后退避清零。
   - 主程序以退出码 0 退出表示用户从托盘退出：等引擎自行退出（最多 5 s，否则结束它），然后整体停止。
   - 引擎以退出码 0 退出时，先等 3 s 再拉起，给主程序留出退出的时间。

子进程不放进作业对象：守护进程自己异常退出时，引擎和主程序继续运行，音频不中断。

```
Aemeath [--data-dir <目录>] [--usbip-port <端口>] [--pipe <管道名>] [--meters <共享内存名>]
```

TaskDialog 需要 Common Controls 6，清单（`guardian.manifest`）由 `build.rs` 嵌入。日志写在数据目录的 `logs\guardian.<日期>.log`。

## 测试

- 单元测试：驱动判定（正常、未安装、过旧、服务未运行、输出无法识别）、对话框语言的选择与文案、监视逻辑（用 `cmd` / `ping` 这类真实小进程，配合很短的退避时间）。
