# aemeath-io

外部设备的 WASAPI 共享流、异步采样率转换（ASRC）桥接，以及主时钟跟随。

## 线程与数据流

每台外部设备一个 IO 线程（MMCSS），与引擎调度线程之间只通过无锁环形缓冲（rtrb）交换音频：

| 方向 | 数据流 | 重采样所在 |
|---|---|---|
| 外部输入 | 设备 → 转立体声 → ASRC → 环形缓冲 → 调度线程每 1 ms 取一块 | 生产方（IO 线程），每次 1 ms 设备帧 |
| 外部输出 | 调度线程每 1 ms 推一块 → 环形缓冲 → ASRC → 设备 | 消费方（IO 线程），每次产出 5 ms 设备帧 |

- ASRC 的比率由 IO 线程里的 PI 控制器按环形缓冲水位每秒调整一次（S5：Kp 40 ppm/ms，Ki 1 ppm/(ms·s)，条件积分，目标 15 ms）。
- 设备按共享模式的混音格式（32 位浮点）收发，不使用 `AUTOCONVERTPCM`（ADR-0010）。单声道复制到左右两路；多声道只用前两路。
- 打不开时报告离线原因（等待设备、被其他程序独占），每 2 秒重试；运行中设备失效（拔出、重新连接，`AUDCLNT_E_DEVICE_INVALIDATED`）同样转为离线并重试，设备回来后自动恢复。
- 事件看门狗：设备被拔出后 WASAPI 不一定再触发事件。超过 1 秒没有事件就查询一次设备，让失效以错误暴露出来；超过 5 秒仍没有事件，按"无信号"关闭这次会话并重新打开。
- 环形缓冲在引擎一侧的那一端被丢弃时（拓扑不再使用这台设备），IO 线程自行关闭设备并退出。
- 外部输出只在设备打开期间接收数据（`active` 标志），离线期间不积压，也不把"没有人消费"误报成丢数据。

## 主时钟跟随（`follow`）

静音另开一条主时钟设备的流，每秒读取 `IAudioClock`：30 s 线性回归测频率，KP 0.1/s 拉相位（S4）。
通过 `ClockTarget` 调整引擎的设备时间线，所以本 crate 不依赖引擎。

## 日志

长期测试（维护者用 Aemeath 实际替代 Voicemeeter 之后的日常使用）出了问题时，靠这些日志排查：

- 每个桥接每分钟一条 `bridge status`：水位范围、误差、漂移估计（积分项）、校正量、溢出帧数、欠载次数、数据不连续次数。
- 主时钟跟随每分钟一条：主时钟相对 QPC 的速率、相位误差、施加的速率。
- 每次会话结束（设备失效、拓扑不再使用、退出）记录一条 `bridge session ended` 汇总。
- 溢出、欠载立即记录（每 5 秒最多一条）；设备打开、离线、失效都有记录。
