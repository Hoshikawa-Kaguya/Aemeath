# aemeath-engine

主时钟调度与路由拓扑的执行。

## 线程模型

| 线程 | 职责 |
|---|---|
| 控制线程（调用 `Engine` 的线程） | 校验拓扑、构建混音器（会分配内存）、设定 USB/IP 导出的槽位、释放调度线程送回的旧混音器 |
| 调度线程 `aemeath-scheduler`（MMCSS Pro Audio，唯一的实时线程） | 完成所有槽位的等时 URB；按时间线每 1 ms 运行一次混音；替换拓扑 |
| USB/IP 读线程（`aemeath-usbip`，每条连接一个） | 解析 URB，以事件交给调度线程 |
| 外部设备 IO 线程（`aemeath-io`，每台设备一个） | 设备流与 ASRC，通过环形缓冲与调度线程交换音频 |
| 主时钟跟随线程（`aemeath-io`） | 按主时钟设备调整设备时间线的速率 |

调度线程用高精度可等待定时器睡眠（最多 0.5 ms），不依赖 `timeBeginPeriod`。

## 模块

| 模块 | 内容 |
|---|---|
| `timeline` | 速率可调的设备时间线。顺序锁实现，读者不加锁；只有一个写者（主时钟跟随，第 5 项） |
| `mixer` | 按拓扑顺序执行通道条、连线增益和求和；增益变化 10 ms 线性过渡；换拓扑时接过旧的当前增益，新连线淡入、删除的连线淡出；记录电平峰值 |
| `slot` | 被导入槽位的流状态：输入方向按时间线放出数据，输出方向按节拍取出并编码 |
| `fifo` | 预分配的立体声环形缓冲 |
| `meters` | 原子变量记录的电平峰值，读取方取走即清零 |
| `port` | 外部设备节点在引擎一侧的端口（环形缓冲的一端）：输入先攒够目标占用再读、读空重攒、积压过多时丢弃；输出只在设备打开时写 |
| `devices` | 控制线程一侧：按"端点 + 方向"复用、新建或停止 IO 线程；切换主时钟跟随 |

## 延迟

- 输入槽位：数据在所属微帧结束后再等 1 ms 放出给混音（吸收主机与引擎分块的 ±1 帧差异），再经过最多 1 ms 的混音块。
- 输出槽位：Windows 每个等时 IN URB 覆盖 10 ms，这段延迟由主机决定。

## 端到端测试

`examples/loopback.rs`：挂载开发槽位 In 1 和 Out 1，拓扑为 In 1 → Out 1；往 In 1 播放 1 kHz 正弦波，从 Out 1 录音，用正弦递推检查每一个样本的连续性。

```sh
cargo run -p aemeath-engine --example loopback --release -- 20 48000
```

`examples/external.rs`：In 1 → 外部输出（−30 dB，同时是主时钟），外部输入 → Out 1。用 WASAPI 环回录下外部输出实际收到的声音并逐样本检查；外部输入的稳定性看日志里的桥接状态。不指定名称时用系统默认设备。

```sh
cargo run -p aemeath-engine --example external --release -- 120 --output "设备名片段" --input "设备名片段"
```

`examples/recovery.rs`：设备拔插自恢复。第二个引擎用开发槽位 In 2 / Out 2 扮演外部设备，被测引擎把它们当作外部输出和外部输入；
中途卸下 In 2 / Out 2（相当于拔出），6 秒后重新挂载，检查被测引擎不重启就能自动恢复，恢复后信号连续。约 80 秒。

```sh
cargo run -p aemeath-engine --example recovery --release
```

开发槽位 Out 2 的共享格式需要是引擎采样率（48k）；Windows 给录音端选的默认格式是 44.1k，正式产品在首次注册槽位时设定。
