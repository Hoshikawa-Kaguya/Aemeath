# aemeath-core

主程序的领域模型（术语见 `GLOSSARY.md`）：工作台上的节点与连线、槽位占用、连线规则，从工作台编译路由拓扑，以及配置文件的读写。

不含运行时状态（设备在线与否、槽位挂载与否），这些属于 `aemeath-control`。

## 规则

`Workspace` 的字段只能通过方法修改，以保证：

- 每个槽位最多被一个节点占用，方向与节点类型一致；新建虚拟节点时自动分配编号最小的空闲槽位，也可以指定。
- 同一个外部设备在同一方向上只对应一个节点。
- 连线检查（`check_route`）给出原因：连到自己、起点不发出声音、终点不接收声音、重复、成环。关闭的连线也算入成环检查。工作台拖线时实时调用。规则本身定义在 `aemeath_protocol::topology::check_route`，与路由拓扑校验共用。
- 节点类型直接使用协议的 `NodeKind`，外部设备的表示换成 `DeviceRef`（端点 ID 加设备名）。
- 删除节点时连同删除它的连线；它是主时钟时清除主时钟设置。
- 节点 ID 只增不减、不复用（引擎换拓扑时按 ID 接过旧状态）。
- 删除的连线可以恢复（撤销），恢复时仍按规则检查。

## 编译

`Workspace::compile(revision)` 生成下发给引擎的路由拓扑。节点名、位置、连线标签位置是界面数据，不进入路由拓扑；外部设备只取端点 ID，设备名留在控制面做后备匹配。

## 配置文件

`ConfigStore`：数据目录下的 `workspace.json`。

- 带结构版本号（`CONFIG_VERSION`）。更新版本写的配置拒绝加载，也不覆盖。
- 先写临时文件再改名。
- 读入后编译成路由拓扑再校验一遍（与引擎的规则相同）。损坏或不合规的文件改名为 `workspace.corrupt-<时间戳>.json` 保留，从空配置开始，并把备份位置告诉调用方。
